# Verify — AishwaryaMasthu

How to run and observe this app locally to verify changes.

## Launch

- `firebase emulators:start --only hosting` serves `public/` on http://127.0.0.1:5000.
- **Gotcha (Windows): the hosting emulator applies NONE of the `firebase.json` `headers` config.** glob-slasher inside superstatic converts globs with `\` separators (`**` → `\**`) and minimatch treats `\` as escape, so every source pattern silently fails to match. Production Firebase Hosting is unaffected. To test headers (CSP etc.) locally, use a small Node static server that reads `firebase.json` and applies matching headers via minimatch with forward slashes (require minimatch from `%APPDATA%/npm/node_modules/firebase-tools/node_modules/superstatic/node_modules/minimatch`).
- Firebase Hosting header matching: request path `/` does NOT match source `**/*.html` — use `**` for headers that must reach the root document.

## Drive

- Headless: `npm i puppeteer-core` in scratchpad + Chrome at `C:/Program Files/Google/Chrome/Application/chrome.exe`. Capture `console`, `pageerror`, `requestfailed` events and screenshot. Pre-login the app shows the login card; the dashboard/tools require real Firebase credentials — verify pre-login surface + static checks for panel content.
- CSP/SRI probes: from `page.evaluate`, inject a script with a wrong `integrity` hash (expect blocked) and a script from a non-allowlisted origin (expect CSP violation).

## Tailwind

- `public/tailwind.css` is compiled (no Play CDN). Rebuild: `npm run build:css` (root package.json; tailwindcss@3.4.17, config `tailwind.config.js`, input `scripts/tailwind.input.css`). Content glob scans `public/**/*.{html,js}` including `public/panels/*.html`.
- After changing `public/` assets, bump `CACHE` version in `public/sw.js` so clients drop stale cached files.
- Known no-op classes that predate the compiled build (not in default Tailwind, never generated by the Play CDN either): `ml-18` (js/cibil.js), `animate-modal` (app.js, index.html, js/fund-picker.js).
